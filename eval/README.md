# Vision 시험 키트 v0.1

벡터에서 뽑은 글자를 정답으로 삼아, 도면 이미지를 모델이 얼마나 정확히 읽는지 자동으로 채점한다.
근거: AI 설계 v0.4 3장(실물 시험), 10장(입력 준비), 14장(평가 계획), 멀티에이전트 구성안 8.1(`eval/run_vision_eval.py`).

## 빠른 실행

```bash
pip install -r requirements.txt

# 1) 데이터 만들기 (DWG→DXF→글자 추출→crop·정답). 약 2분. 이미 data/에 만들어져 있으면 생략
python prepare_vision_kit.py --dwg "../../02_1년치_조사/3_도면판정_78건/DWG모음/R26BK01381968_고려대 도면.dwg"

# 2) 채점기 자체 점검 (100%가 나와야 정상)
python run_vision_eval.py --provider gt

# 3) 실제 모델 (도면 crop이 외부로 나간다 — 아래 '외부 전송' 확인 후)
set ANTHROPIC_API_KEY=...   /  set OPENAI_API_KEY=...
python run_vision_eval.py --provider openai    --model gpt-6-luna       --tiles 2 --repeat 3
python run_vision_eval.py --provider anthropic --model claude-haiku-5-5 --tiles 2 --repeat 3

# 4) 단위 시험 (네트워크 없이)
python -m pytest -q tests
```

주요 옵션: `--tiles N`(N×N 조각, 기본 2), `--repeat`, `--regions legend,equipment,plan_3f`,
`--effort`(추론 강도), `--detail`(Luna 이미지 detail), `--timeout`(초, 기본 120), `--concurrency`(기본 4),
`--max-side`(조각 긴 변 상한, 기본 8000px), `--base-url`(openai_compat).

## 데이터 (data/vision_v0.1)

원본: 고려대 세종캠퍼스 행정관 DWG (R26BK01381968, AC1024). SHA-256은 `manifest.json`.

| 영역 | 내용 | 정답 글자 | 이미지 | AI 설계 3장과의 관계 |
|---|---|---:|---|---|
| `legend` | 지하 1층 냉난방배관 평면도의 기호표(RGRLV 블록): 관경 기호 A~I, 액관·가스관 | 30 | 999×1190 | "기호표 30개"와 같은 블록 |
| `equipment` | 장비일람표 (실내기 7종 + 실외기 5종 표) | 239 | 8646×4023 | "장비일람표 239개"와 같은 범위 |
| `plan_3f` | 3층 냉난방배관 평면도 일부: 배관 기호(A~K), 2.0HP·EHP, 실명 | 34 (채점 32) | 6437×3277 | "평면 29개"와 같은 영역인지 기록이 없어 **새로 고름**. 로컬 OCR 17%와 직접 비교 불가 |

- 정답 = 렌더 범위 안에 상자 중심이 있는 **인쇄되는 글자 전부**. 이미지 가장자리에서 잘린 글자는 채점에서 뺀다 (plan_3f 2개).
- 글자 수 확인: 인쇄 레이어 글자(치수 제외) **6,201개**로 AI 설계 3장 기록과 일치. 치수 글자는 이미지에 보이므로 정답에 포함한다 (세 영역에는 0개).
- 해상도: 영역에서 가장 작은 글자가 40px이 되게 그린다 (10장: 32~48px).

## 지표 (report.md, scores.json)

| 지표 | 정의 |
|---|---|
| 재현율 | 채점 대상 정답 글자 중 맞게 읽은 비율. 정답 글자가 들어 있는 조각 중 하나에서라도 맞으면 맞음 |
| 숫자 칸 재현율 | 숫자가 든 정답 글자만 센 재현율 (14.2 '숫자 칸 정확도') |
| 정밀도 | 모델이 낸 글자 중 정답과 짝지어진 비율. 쪼개 읽기·중복·없는 글자는 오답 |
| 반복 편차 | 같은 입력을 `--repeat`번 돌렸을 때 재현율 최대−최소 (%p) |
| 호출 시간 | p50·p95 (ms) |
| 비용 | 토큰 × 단가 (단가는 `run_vision_eval.py`의 `PRICES`, AI 설계 2장 기준). 1,000회당 비용도 낸다 |

맞음 판정: 정규화(NFKC로 전각·㎟ 변환, Ø·φ·ø 통일, 공백 제거) 후 **글자 덩어리 단위로 정확히 같아야** 한다.
조각 경계에 걸린 글자의 일부를 읽은 것은 맞음도 오답도 아니다(무시). 실패한 호출은 그 조각 전체를 놓친 것으로 센다.

## 한계

- 글자 상자는 근사값(글자 수 × 높이 × 0.8)이라 경계 판정이 몇 px 틀릴 수 있다.
- 정확히 같아야 맞음으로 센다. 한 글자 틀림과 완전히 틀림을 구분하지 않는다.
- 교차 확인 비교(두 결과 맞대기), 로컬 OCR 기준선 재측정, V1 연결 판단(YES/NO/UNSURE) 시험은 아직 없다.
- 모델 쪽에서 큰 이미지를 내부적으로 줄이는지(조각 크기 4,600px 안팎)는 확인하지 않았다. 결과가 낮으면 `--tiles 3`과 비교한다.
- 실제 모델 호출은 아직 돌리지 않았다. 공급자 코드는 가짜 HTTP 응답으로만 시험했다 (`tests/test_providers_offline.py`).

## 외부 전송

실제 모델을 부르면 도면 crop이 OpenAI·Anthropic으로 나간다. AI 설계 16장에 따라 제공처와 팀의 동의를 받은 뒤 실행한다.
API 키는 코드·저장소에 넣지 않고 환경변수로만 준다. 결과 폴더(`results/`)에는 모델 응답 원문이 저장되므로 저장소에 올리지 않는다.
