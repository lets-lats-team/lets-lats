## clause_no 규칙 (정답 입력과 pair_key가 같은 문자열을 쓴다)

경로의 번호 표시를 공백으로 잇는다. 소수점 번호(1.1.7)는 그 자체가 번호다. `□`는 원문에 번호가 없어 문서 안 순서로 붙인다.

| 세트 | 원문 구조 | clause_no 예 | 조항 수 |
|---|---|---|---|
| S24 HWP | □ 덩어리마다 1.부터 다시 → 가. → ① / (1) | `□2 3. 아.` | 88 |
| S25 HWP | 제N장 → 1.1 → 1.1.7 → 1) → ① (3장은 3.2 → 1. → 1) → (1) → ①) | `1.1.7 2)`, `3.2 3. 8)` | 315 |
| S26 PDF | 1~47쪽 공통시방서(□, 첨부N, 서식N), 48~57쪽 제N장 → 1. → 1) → (1) → ① | `제2장 3. 8)` | 301 |

- 목차("목차" 줄부터 첫 항목이 본문에 다시 나오기 전까지)와 첫 조항 앞(표지)은 뺀다
- 번호가 이어지지 않는 줄(+1·+2도 1도 아님)은 끊긴 문장으로 보고 본문에 붙인다. 소수점 번호는 뒤에 한글 제목이 오고 장 번호와 첫 자리가 같을 때만
- 원문 특성 메모 2건 (S25): `2.3.7 10)` 원문이 8) 다음 10) (번호 건너뜀), `3.2 3.` 원문 "3 냉매 배관" (마침표 없음)
- S26 글자층 없는 쪽: 23~47 (25쪽). V4 후보로 기록만 한다 (정답셋 메모의 22~47과 1쪽 차이: 22쪽은 '첨부5 그라운드 룰' 제목 글자가 있음)

## 결정 (2026-11-25 김선진)

- **clause_no 표기**: 위 표의 규칙 그대로
- **인용문 대조 (G2)**: 공백 전부 제거 + 전각→반각·Ø 기호·단위 표기(NFKC)·물결 통일·표 칸 구분자 `|` 제거 뒤, 모델이 든 clause_no 조항(하위 조항 포함) 원문 안에 quote가 들어 있으면 통과. **숫자 조건이면 value의 숫자가 quote 안에도 있어야 통과.** 아니면 AI_NO_EVIDENCE
- **연산자 (2026-11-26 확정, 11-25 결정 (가) 10개를 되돌림)**: 설계서 11.4대로 `=`, `!=`, `>=`, `<=`, `>`, `<` 6개. 범위 "A~B"는 `>=`·`<=` 두 규칙(기울기 분수는 값 크기로: 1/50~1/100 → `>=` 1/100, `<=` 1/50), 금지·제외는 `!=`, 그 밖(포함·구성)은 자재·부속처럼 맞댈 수 있으면 `=`, 아니면 뽑지 않음. G3: `~`로 이은 숫자 범위 값은 AI_OUT_OF_DOMAIN. 평가: 6개 밖 연산자 정답 행은 채점에서 빼고 report.md '정답 입력 점검'에 행 번호를 적음
- **추출 범위**: S26 1~47쪽도 보내되, 프롬프트에 "냉난방·배관 시공 조건만, 서류·안전·감염관리·서약 등은 뽑지 않는다"
- **정답 입력 가이드**: 데이터 폴더(`LETS_DATA_ROOT`)의 정답셋 폴더 `L3_정답입력_가이드.md` (프롬프트 l3-v2와 같은 규칙. 규칙을 바꾸면 둘 다 바꾼다. l3-v3 차이는 아래 '실제 모델 시험')
- **공사 방식 행 형식**: 설계서 형식대로. 행 7칸은 그대로 두고 item `냉매 배관`, attribute `공사 방식`, operator `=`, unit 빈칸, value는 R01 4종 코드(`NEW_ROUTE`·`REUSE_ROUTE`·`REPLACE_AFTER_DEMO`·`REUSE_PIPE`) 중 하나. 원문 문구는 quote(D06 raw_value)에 있다. G3: 형식이 어긋나거나 4종 코드를 다른 attribute에 쓰면 AI_OUT_OF_DOMAIN (G2 다음, 단위 검사 앞). D06 value_key는 `spec:냉매 배관:공사 방식`
- **4종 코드 고르는 기준** (프롬프트·가이드): 일부라도 기존 냉매 배관을 다시 쓰면 `REUSE_PIPE`, 철거 후 신설이고 경로 말이 없으면 `REPLACE_AFTER_DEMO`, 철거 후 기존 경로로 신설이면 `REUSE_ROUTE`, 새 경로 명시만 `NEW_ROUTE`. 드레인만·제목·공사 범위 나열 속 '배관 교체'는 안 뽑는다. 말이 없으면 안 뽑는다 (기본값 `NEW_ROUTE`는 A03 몫)

- **인용문·값 검사 보강 (2026-11-26)** — 모델 답을 일부러 틀리게 바꿔 넣는 검증에서 통과하던 경우를 막은 규칙
  - G2: 글자 값(공사 방식 코드 제외)도 quote 안에 그대로 있어야 통과 (규격 번호 `KSC9306`을 `KSC0417`로 바꿔도 통과하던 것). 영숫자로 끝나는 글자 값은 quote에서 앞뒤가 다른 영숫자와 이어지면 안 됨(`KSC930`이 `KSC9306` 안에서 통과하던 것). 숫자는 수 값으로 비교(`3.80` = `3.8`)
  - G2 공사 방식: 코드별 근거 말이 quote에 있어야 함 — REUSE_PIPE 재사용·재활용·"기존 … 사용", REPLACE_AFTER_DEMO 철거·교체·재시공, REUSE_ROUTE 경로, NEW_ROUTE 경로·신설·신규
  - G3: 범위 표기(`~`·`-`·`내지`·`—`·`−`)는 값 전체가 "숫자 구분자 숫자[단위]"일 때 보류 (앞 `-`는 음수, `KS D 5301-2`는 통과). 숫자+단위·관경 기호를 value에 붙여 쓰면 보류(`30A`, `1.5m`, `Ø6.35`, `30A이상`, `-10℃`, `3대`). 빈 값 보류. 공사 방식 item은 `냉매 배관`만
  - clause_no 맞추기 (김선진 결정): quote가 든 가장 아래 조항으로 내림(다른 묶음의 하위 조항 포함, private `tree`). `#2` 꼬리만 다른 같은 번호 중 하나에만 quote가 있으면 그것으로. 모델이 든 번호의 하위 밖으로는 옮기지 않음. 바뀌면 Candidate.note에 `clause_no 조정`
  - 조항 나누기: 한 줄에 문장 끝 + 다음 순서 번호가 붙으면 나눔 (S25 `3.2 4. 2)` 한 곳). 긴 한 줄은 자르지 않고 조각으로 나눔(뒷부분이 빠지던 것)
  - 묶음 크기: chunk_tokens에 머리말 포함
  - 평가: 같은 pair_key 결과가 여러 묶음에서 나오면 한 번만 셈('중복 결과'), 같은 키 정답 여러 줄은 하나와 같으면 맞음. 대표 판정은 PENDING을 보류보다 앞에
  - 같은 조항에서 item·attribute·operator가 같은 규칙을 둘 내면 엔진이 AI_OUT_OF_DOMAIN으로 막으므로 프롬프트·가이드에 "값이 여럿이면 한 value에"
  - 한계(그대로 둠): 같은 문장에 숫자가 여럿이면 G2는 숫자가 어느 항목 것인지 모름(25A·30A — 교차 확인 G5 몫), 떨어진 글자 값(`인탈산 재질의 동관`), 드레인·배관커버 재사용을 냉매 배관으로 착각할 수 있음(G5·A03 몫), "기존 … 사용"이 다른 뜻 문장에 걸릴 수 있음, 이어짐 조각의 근거 범위, S26 다쪽 조항의 쪽 표시, 공고문 HWP 자동 번호·붙임 반복 번호
