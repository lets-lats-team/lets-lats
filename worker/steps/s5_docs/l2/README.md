## 하는 일

| 단계 | 누가 | 내용 | 파일 |
|---|---|---|---|
| 읽기 | 코드 | `.xlsx`(openpyxl)·`.xls`(xlrd) → 같은 모양. 병합 셀, 숨김 열, 소수점 찌꺼기 정리 | `../reader_xlsx.py` |
| 머리글 | 코드 | 품명 계열(품명·명칭·공종·품명및규격·공종명·품목·품목명)과 '단위'가 같은 행 (공백 무시), 두 줄 머리글은 `윗줄 / 아랫줄`. 못 찾으면 사유를 메모에 | `../boq_header.py` |
| 작업 1 `BOQ_SHEETS` | 모델 | 시트마다 시트 종류 + 수량 시트 여부 (Y/N) | `tasks.py`, `prompt.py` |
| 작업 2 `BOQ_COLUMNS` | 모델 | 수량 시트의 열 역할 + 머리글 인용 (숨김 열 포함, "(숨김)" 표시). **머리글이 없는 열은 보내지 않고 코드가 '기타'** (후보 이름 `코드 규칙`) | 〃 |
| 작업 3 `BOQ_ROWS` | 모델 | 머리글 아래 행을 50행씩 분류 (숨김 열 값은 보내지 않음) | 〃 |
| 검사 | 코드 | G1 스키마, G2 머리글 인용 대조, G3 값 목록·중복·누락·품명/단위/수량 열 하나씩 | `gates.py` |
| 교차 확인 | 코드 | 두 모델 항목별 비교 → 같으면 PENDING, 다르면 AI_DISAGREE, 한쪽 실패면 AI_NO_RESPONSE | `pipeline.py` |
| 수량 시트 안전장치 | 코드 | 원가계산서·일위대가 등을 Y로 답하면 보류 (아래 2026-11-25 수정) | `gates.rule_qty_sheet` |
| 값 연결 | 코드 | 품목 행의 품명·규격·단위·수량을 **원본 셀에서** 가져옴 (모델 숫자 안 씀). 품명·단위·수량 열이 모두 PENDING일 때만 | `extract.py`, `pipeline.py` |

값 목록은 정답셋 엑셀 '목록' 시트와 같다 (`vocab.py`).
모델 호출은 이 코드가 하지 않는다. `run_l2(path, call, primary, verifier)`의 `call(task, model)`로 받는다 (gateway는 공통 담당).
작업은 계약의 AITask 모양 dict (`role`, `target_key`, `payload`, `affects_output`)이다.

## 실행 명령

```bash
cd lets-lats
python -X utf8 -m pytest -q -p no:cacheprovider worker/tests eval/tests   # 단위 시험 30개 (가짜 내역서, 2026-11-25)

cd eval
python run_l2_eval.py --primary gt                    # 자체 점검: 정답이 있는 항목 전부 맞아야 정상
python run_l2_eval.py --primary fake-wrong            # 틀림을 잡는지
python run_l2_eval.py --primary gt --verifier fake-wrong   # 교차 확인: 틀린 PENDING 0, 불일치는 AI_DISAGREE
# 실제 (동의 후): python run_l2_eval.py --primary gpt-6-luna --verifier claude-haiku-5-5
```

정답 파일 기본값: 데이터 폴더(`LETS_DATA_ROOT`)의 정답셋 폴더 `정답_입력완.xlsx` (읽기 전용, `--answers`로 바꿈).
결과: `eval/results/l2_<시각>_<모델>/` — 세트별 `L2_시트구분`·`L2_열대응`·`L2_행분류`·`L2_품목값` CSV(정답 엑셀과 같은 칸 + 상태·hold_code·모델별 후보), `report.md`.

## 코드 안전장치 (2026-11-25)

모델 답을 일부러 틀리게 바꿔 넣는 검증과 3년치 내역서 전수 스캔에서 나온 문제를 코드 규칙으로 막았다. 프롬프트는 바꾸지 않았다 (`L2.v4`).

| 무엇이 문제였나 | 규칙 | 위치 |
|---|---|---|
| 모델이 `일위대가`를 수량 시트 Y로 답하면 단가 산정용 자재가 품목으로 나감 (김선진 결정 가) | 규칙① 시트 종류가 원가계산서·집계표·일위대가·단가대비표·표지인데 Y → 보류. 규칙② 시트 이름(공백 무시)에 일위대가·단가대비·원가계산·집계가 있는데 Y → 보류. 보류 코드 `AI_OUT_OF_DOMAIN`, 모델 답은 `모델별 후보`에 보존, 시트 메모에 걸린 규칙과 사유, 시트구분 CSV `규칙 보류` 열, report.md에 "수량 시트 규칙 보류 N건"과 시트별 목록(정답이 Y면 **오보류** 표시) | `vocab.py` `NON_QTY_*`, `gates.rule_qty_sheet`, `pipeline.py` |
| 수량 열이 보류됐는데 수량 없는 품목이 나감 (S24 99건) | 품명·단위·수량 열 중 하나라도 PENDING이 아니면 그 시트의 품목을 내보내지 않음. 행 분류 결과는 남김. 메모·report.md에 사유 (예: `수량 열 보류 D(AI_DISAGREE, 후보 gt=수량·wrong_qty=기타)`, `단위 열 없음`) | `pipeline._missing_item_cols`, `SheetResult.items_blocked` |
| `품목`·`품목명` 머리글을 못 찾음 | 품명 계열에 `품목`·`품목명` 추가 | `boq_header.NAME_KEYS` |
| 머리글 미탐지 메모가 한 줄뿐 | 몇 행까지 봤는지, 품명 계열만 있는 행, 단위만 있는 행, 수량은 있고 단위 열이 없는 행(셀 주소와 글자)을 메모에 | `boq_header.header_diagnosis` |
| 단위 열 없이 수량 칸에 "14대"로 적는 간이 양식 (김선진 결정 나) | **지원하지 않음.** 해당 공고 2개에는 표준 양식 `세부내역서` 시트가 따로 있어, 지원하면 물량이 중복된다. 머리글 미탐지 메모에 "간이 양식일 수 있음 (지원하지 않음)"만 표시 | `boq_header.header_diagnosis` |

확인 (모델 호출 없음): 단위 시험 30개 통과. gt·fake-wrong·교차 조합의 채점 수치가 규칙을 넣기 전과 같음. 3년치 내역서에서 머리글이 새로 잡힌 시트 65개(11파일)는 모두 "못 찾음 → 찾음", 기존 머리글이 바뀐 시트 0개.

실제 모델 결과에서 볼 것
- 새로 머리글이 잡힌 시트 중 이름이 `일위`·`CODE1`인 것은 규칙②에 걸리지 않는다. 모델이 시트 종류를 일위대가·단가대비표로 맞게 답해야 규칙①로 막힌다. Y로 가는지 확인
- 두 열 머리글이 모두 `품목명`인 내역서: 모델이 둘 다 품명으로 답하면 G3로 둘 다 보류 → 품목을 내보내지 않음. 실제 결과에서 확인
- 실제 결과의 `L2_행분류`에서 틀린 PENDING의 원본 위치(시트·행)와 기대값/실제값
- S26 `일위대가`·`단가대비표`가 수량 시트(N)로 판정되는지, 머리글을 못 찾는 양식이 조용히 빠지지 않고 메모에 사유가 남는지, `.xls` 내역서가 같은 결과 모양으로 나오는지
